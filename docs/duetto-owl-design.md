# Duetto 形象设计方案

> 本文记录为什么最终选择「小猫头鹰」，以及每个设计决策背后的依据。
> 竞品原始数据见 [duetto-eye-design-research.md](duetto-eye-design-research.md)。

---

## 一句话

**屏幕只负责「瞳」和「脸」，眼周的「面盘」交给绕屏灯带。** 这样既像鸟，又保住了屏幕的灵活性——这是猫头鹰方向的破局点。

---

## 为什么不做纯几何（Vector / Cozmo 路线）

调研的结论是「抽象几何」在单位成本和迭代速度上占优，但 Duetto 有三个特殊约束让纯几何不合适：

| 约束 | 纯几何的问题 | 猫头鹰的优势 |
|---|---|---|
| 要表达「听歌情绪」 | 两个圆点说不出"我在为这首歌感动" | 鸟的表情词汇天然丰富（受惊、专注、犯困、欢唱） |
| 要做双人陪伴 | 抽象形象会让两人产生"我用的是设备"的距离感 | 生物形象更容易产生"我们共同养了一只"的归属感 |
| 要配合舵机 | 抽象形象摇头会显得莫名 | 鸟本来就会转头，舵机动作有天然语义 |

所以折中方案是：**用抽象几何的绘制手法（实心色块、极简轮廓、无贴图）去画一个具体的生物**。这也是调研里"抽象几何为主线 + 局部拟物符号"的具体落地。

---

## 三个关键设计决策

### 决策一：不画眼白 + 瞳孔

**依据**：Cozmo 和 Vector 都是单色填充形状，Anki 直接把 Wall-E 里 Eve 的眼睛搬过来。小屏画眼白会立刻显脏、显小。

**实现**：眼睛是两块实心琥珀色 `#FFD98A`，没有眼白、没有瞳圈、没有高光点。

**放弃的东西**：很多教程会教"眼白 + 虹膜 + 瞳孔 + 高光"四层结构，240px 上根本放不下，四层颜色叠起来就是一坨灰。

### 决策二：滑动是「转头」，不是「转眼」

**依据**：真实猫头鹰的眼球固定在眼窝里，不能转动。竞品调研也验证了这点（Bubo-2T 用机械眼睑 + 眼环，屏幕不负责转）。

**实现**：

```
col.pos (-1..1)  ─┬→  head_x     = col * 0.115   整张脸平移
                  ├→  head_tilt  = col * 9.0°    整张脸旋转
                  └→  servo       = 90° + col*18° 舵机摆头
```

屏幕上**不画瞳孔位移**。

**额外收益**：舵机从"可有可无的装饰"变成了"转头动作的执行者"，硬件有了存在理由。

### 决策三：一次只动一条边

**依据**：调研原则第 3 条——上缘上凸=开心，上缘下压=困，下缘抬尖=不屑。两边同时动会读不懂。

**实现**：`eye_shape()` 三个独立通道

```python
eye_open   上缘高度     1=正圆   <1 眯眼(困)   >1 瞪大(惊)
smile      上缘中段上凸  用于笑眼
angry      上缘整体倾斜  用于专注/生气
```

同一帧最多只让一个通道有明显变化，其余保持 0。

## 猫头鹰的三个识别符号

去掉眼白之后，眼睛就是一个色块，必须靠别的东西建立"鸟感"。三个符号缺一不可：

### 1. 面盘（facial disc）

猫头鹰最标志性的特征。实现是一个**顶部带心形凹口的椭圆**：

```python
notch = 0.26
if y < 0:
    k = max(0, 1 - abs(x)/0.55)   # 中间 1，两侧 0
    y *= (1 - notch * k * k)      # 中间往上收，形成凹口
```

屏幕上的面盘是暗色 `#3A2D22`（不是浅色），因为**真正的"亮面盘"由绕屏灯带承担**。屏幕上画深色是让眼睛成为最高对比度的元素。

### 2. 眉羽

**这是最容易画错的地方。** 第一版我画了一条实心斜线，结果看起来像人类的眉毛，整只鸟变成了"生气的人"。

改成**三根由粗到细的羽片叠出层次**：

```python
LAYERS = [ (offset=0.000, width=1.00, shorten=0.00),
           (offset=0.052, width=0.62, shorten=0.16),
           (offset=0.098, width=0.40, shorten=0.32) ]
```

三根连在一起看是一束羽毛，单独看每根都有粗细变化。

眉羽的三个参数：`brow_lift`（整体上扬）、`brow_asym`（左右一高一低，配合转头）、`brow_flare`（炸开，彩蛋用）。

### 3. 喙

一个倒三角，作用是**把两只眼睛连成一张脸**。没有它在，两个色块就只是两个色块。

张开时拆成上喙 + 下喙，中间露出深色口腔 `#341E12`。

## 配色

| 用途 | 值 | 说明 |
|---|---|---|
| 屏幕底 | `#14100C` | 暖褐黑，比纯黑柔和，夜里看不刺眼 |
| 面盘 | `#3A2D22` | 深褐，只做轮廓暗示 |
| 眼睛 | `#FFD98A` | 琥珀，是整块屏幕唯一的高亮色 |
| 眉羽 | `#6C543E` | 比面盘深，比眼睛暗很多，不抢视觉 |
| 喙 | `#E29646` | 暖橙，和眼睛同色系但更饱和 |
| 灯带（我） | `#FFB86B` | 暖 |
| 灯带（对方） | `#6FD3FF` | 冷 |

**只有眼睛是高亮的**——这样在任何表情下，用户的视线都会被引导到眼睛上。

## 手势 → 表情映射

| 手势 | 屏幕 | 灯带 | 舵机 |
|---|---|---|---|
| 轻敲 | 眯眼（`eye_open` 降到 0.5）+ 整体下沉 + 眉羽微扬 | 左右同亮暖白 | 轻微下沉 |
| 重击 | 沉得更低更久 + 眉羽压低（`angry`）+ 眼睛瞪大 | 同亮橙色 | 下沉更深 |
| 左滑 | **整脸左移 + 左转 9°** | 左侧暖亮、右侧冷暗 | 左转 18° |
| 右滑 | **整脸右移 + 右转 9°** | 左侧冷暗、右侧暖亮 | 右转 18° |
| 上滑 | 笑眼（`smile`）+ 张嘴 + 左右跳动 | 融为一体暖黄 + 星星 | 抬头 |

## 已完成的两个「共鸣」设计

### 心形眼睛

上滑彩蛋触发后，眼睛会**周期性地从圆变心形再变回来**（不是一直心形，否则会腻）：

```python
ph = (clock * 1.6) % 1.0
heart = max(0, sin(pi * min(1, ph * 2.2))) * (hype - 0.45) / 0.55
```

形变用极坐标心形曲线和圆做**插值**，所以是平滑变形不是跳变。同时两眼间距收拢 14%——"靠在一起"是共鸣最直接的视觉隐喻。

### 待机微动

`idle_x` / `idle_y` 在待机时缓慢随机漂移（每 2–5 秒换一次目标），让静止的猫头鹰看起来还在"看东西"。调研里 Moflin 没有任何屏幕却依然成立，证明"活着"可以由细微的非大动作承担。

- [ ] **灯带的「左右分区」在圆形排布下，物理上是左右还是上下？** 绕屏一圈的灯带，0° 和 180° 的位置关系需要实物确定后重新映射。
