## 1. 先看证据：现在的猫头鹰到底哪里不对

### 1.1 缩到真实尺寸后，它像一张生气的脸，不像鸟

把 240×240 的渲染结果缩到 64px 再放大（模拟 1.24 寸屏在正常观看距离下占据的视角），得到的结果是：

![真实尺寸下的识别度](../preview/owl_silhouette_test.png)

两只大眼 + 倒三角 + 上方两条斜线 —— 这是**人类表情符号**的语法（`>_<` 那种「不爽脸」），不是鸟。核心问题：**眉羽在小尺寸下被读成人类的眉毛，喙被读成人类的鼻子。**

### 1.2 元素拆解实验：喙反而降低了猫头鹰识别度

只画不同元素组合，看哪一组最像猫头鹰（从左到右 A→E）：

![最小识别特征集](../preview/owl_minfeatures.png)

| 组合 | 结果 |
|---|---|
| A 只有眼睛 | 两个黄椭圆，无物种信息 |
| B 眼 + 喙 | **像一张脸**（眼+鼻），最容易误读成人 |
| C 眼 + 面盘（带凹口） | 开始有鸟感，凹口是关键 |
| D 眼 + 面盘 + 眉，**没有喙** | **最像猫头鹰** |
| E 眼 + 面盘 + 眉 + 喙（当前方案） | 比 D 差，喙把注意力从「面盘」拉向「人脸」 |

**结论：猫头鹰的识别度来自「两块病毒面盘 + 中间凹口」，不是喙。** 现在的实现把喙做得太抢眼（暖橙色、高对比、纯几何三角），而面盘几乎看不见——正好弄反了主次。

### 1.3 面盘对比度只有 1.42:1，等于没画

用 WCAG 相对亮度公式实测当前配色：

| 比较 | 对比度 | 判断 |
|---|---|---|
| 背景 vs 面盘 | **1.42 : 1** | 几乎看不见，面盘白画了 |
| 面盘 vs 眼睛 | 9.85 : 1 | 充足 |
| 背景 vs 眼睛 | 14.01 : 1 | 充足 |
| 面盘 vs 眉羽 | 1.89 : 1 | 眉羽糊在面盘里，边界不清 |

1.42:1 是什么概念——WCAG 对正文的要求是 4.5:1，对大字是 3:1。1.42 连「能看出有块东西」都勉强。

这就是为什么现在看起来「脏」：面盘的形**存在但不可见**，于是观感退化成「两个眼睛浮在黑底上」，再被眉羽和喙强行拼成一张人脸。

### 1.4 眼距偏宽，落进了「像人」的区间

![眼距对比](../preview/owl_eyegap.png)

从左到右眼距 0.85x / 1.0x / 1.2x / 1.45x。眼距越大越像人（人类眼距约 1 个眼宽），越小越像鸟/幼崽。当前值 1.0 落在偏人的一侧；猫头鹰该更靠左，约 0.7~0.85。

### 1.5 眉羽的语法错了

现在用 3 根锥形羽片叠出「羽束」感，设计意图正确，但在 240px 上：
- 3 层羽片的色差只有 12/10/8，缩略后完全糊成一块
- 角度太陡（近似 20°），读成「怒眉」而不是「猫头鹰的眉骨」
- 眉羽底部没和面盘凹口衔接，中间是断的

## 2. 可执行的设计规则（基于上面的测量）

### 规则 1：面盘要能看见——对比度至少 3:1

- 背景 `#14100C`（暖褐黑）保持
- 面盘提到 ≥ `#4A3A29` 区间，实测能把对比度拉到 2.8~3.2:1
- **更省事的做法**：面盘不做「填充色块」，而是做**灯带的面盘外环 + 屏幕上的细描边**。屏幕只负责眼睛，面盘交给物理灯带（这一点前一篇调研的「方向 B」已经提过，但当前实现没执行）

### 规则 2：删掉喙，或把它降级成极小的暗示

按 1.2 的实验，猫头鹰的识别靠面盘凹口。喙应该：
- 缩小到现在的 40% 以下，或者
- 改成**低对比度的深色小三角**（和面盘同色系，只靠明度差），或者
- 只在「张嘴欢呼」时出现

现在的高饱和暖橙 `#E29646` 是全场最亮的第二色，抢了眼睛的位置。

### 规则 3：眼距压到 0.7~0.85

当前 `eye_gap=1.0`，建议默认改 0.8。同时**虹膜/瞳孔几乎不左右位移**——猫头鹰眼球不能转，「看向哪边」完全靠转头。这一点当前实现做对了，保持。

### 规则 4：眉羽改成「面盘的边缘」而不是独立元素

- 去掉 3 层叠片（低分辨率下无意义，还多 6 个图元）
- 改成 1 个和面盘同色的多边形，作为面盘凹口两侧的「上沿外翻」
- 或者直接把眉羽做成**眉骨阴影**：比面盘深 1 档的半透明形状，只在眼睛上方

这样「眉」是脸的一部分，而不是贴上去的两条线——就不会被读成人类眉毛。

### 规则 5：颜色只用两个饱和色

现在有：琥珀眼、暖橙喙、米白面盘、棕色眉羽、深靛蓝羽毛（定义了没用）。太多。

建议收到：
- 眼睛：琥珀 `#FFD98A`（唯一高饱和）
- 面盘：暖白或暖褐，低饱和
- 其余一切用中间调，且都从面盘色派生

### 规则 6：静态「形状语言」和动态「表演」分开设计

这是当前最大的结构性问题：`duetto_owl.py` 里形象和表情参数是混在一起的，导致**为了做表情而改坏造型**（比如 angry 通道一开就变成人脸的怒眉）。

应该拆成：
- **造型层**（固定不变）：面盘、眼位、色板 —— 决定「它是谁」
- **表演层**（可插值）：眼睑开合、眉骨升降、转头 —— 决定「它在做什么」

好的角色设计里，这两者正交。现在 8 个参数里有一半同时在影响两者。

## 4. 如果重做，我会这么排优先级

1. **先修对比度**（规则 1）—— 1 小时，立刻见效
2. **删喙 / 压眼距**（规则 2、3）—— 半天，是「像鸟」还是「像人」的分水岭
3. **眉羽并进面盘**（规则 4）—— 一天
4. **拆造型层与表演层**（规则 6）—— 结构重构，最花时间但决定后续迭代速度
5. 配色收敛（规则 5）

前两步做完就值得再看一次真实尺寸效果，很可能不需要动架构。
